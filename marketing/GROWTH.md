# PART 1. 전문가 방법론 학습

실무에서 실제로 쓰이는 것만. 유행어는 뺐다.

## 1.1 Bullseye Framework — 채널을 "고르는" 방법

Gabriel Weinberg(DuckDuckGo 창업자) & Justin Mares, *Traction*.
핵심 주장: **스타트업이 죽는 이유의 절반은 제품이 아니라 채널을 못 찾아서다.**
그리고 대부분의 팀은 자기가 편한 채널 2~3개만 편향적으로 시도하다 끝난다.

19개 채널 (전부 검토가 강제 규칙):

| # | 채널 | # | 채널 |
|---|---|---|---|
| 1 | Targeting Blogs (틈새 블로그 타깃) | 11 | Engineering as Marketing (무료 툴) |
| 2 | Public Relations (언론 보도) | 12 | Business Development (제휴) |
| 3 | Unconventional PR (비정형 PR·스턴트) | 13 | Sales (직접 영업) |
| 4 | SEM (검색 광고) | 14 | Affiliate Programs |
| 5 | Social & Display Ads | 15 | Existing Platforms (기존 플랫폼 기생) |
| 6 | Offline Ads | 16 | Trade Shows (산업 전시회) |
| 7 | SEO | 17 | Offline Events |
| 8 | Content Marketing | 18 | Speaking Engagements (강연) |
| 9 | Email Marketing | 19 | Community Building |
| 10 | Viral Marketing | | |

**프로세스 (5단계)**

1. **Brainstorm** — 19개 전부에 대해 "우리라면 어떻게?"를 억지로 1줄씩 쓴다.
   목적은 아이디어가 아니라 *편향 제거*. 여기서 채널을 미리 탈락시키면 안 된다.
2. **Rank** — 3개 동심원에 배치.
   - 외곽(C): 가능은 함 / 중간(B): 그럴듯함 / 과녁(A): 유망
3. **Prioritize** — A에 정확히 **3개**만. 기준은 *"흥미도가 눈에 띄게 꺾이는 지점"*.
4. **Test** — 3개를 **동시에**, 싸고 빠르게. 각 테스트가 답해야 할 질문 3개:
   - CAC(획득 단가)는 대략 얼마인가?
   - 이 채널에 남아있는 고객 물량은 얼마인가? (포화점)
   - 여기서 온 고객이 우리가 원하는 고객인가?
   → 테스트 설계 원칙: *"페이스북 광고 40개 말고 4개를 돌려라."* 수백 달러 수준.
5. **Focus** — 신호가 가장 강한 **하나**에 자원 몰빵. 포화되거나 단가가 오를 때까지.

**중요한 경험칙**: 성숙 단계마다 이기는 채널은 바뀐다. Mint는 타깃 블로그로 4만 명까지
갔다가 포화되자 PR로 갈아타 6개월 만에 100만 명을 만들었다.
→ *"지금 우리 단계의 채널"* 이라는 개념이 있다. 영구적 정답 채널은 없다.

## 1.2 Growth Loops — 퍼널을 버려야 하는 이유

Brian Balfour (Reforge), Casey Winters, Kevin Kwok, Andrew Chen.

퍼널의 문제:
- **선형**이다. 입력을 넣은 만큼만 출력이 나온다. 광고를 끄면 0이 된다.
- **사일로**다. 마케팅/제품/수익화가 따로 논다.
- **일회성**이다. 출력이 다시 입력이 되지 않는다.

루프의 정의: **출력이 다시 입력으로 재투자되는 닫힌 계.**
그래서 복리로 자란다. 형태는 4가지 — 바이럴 루프, 콘텐츠 루프, 유료 루프, 세일즈 루프.

우리에게 해당되는 건 **콘텐츠 루프**다. 전형적 구조:

```
데이터/콘텐츠 생성 → 검색·소셜 노출 → 방문자 유입 →
  일부가 구독/공유/인용 → 다음 콘텐츠의 배포력·권위 상승 → (처음으로)
```

루프를 설계할 때 반드시 명시해야 하는 것:
- **입력**이 무엇인가 (매달 갱신되는 행안부 원본 데이터)
- **한 사이클의 소요 시간** (월 1회? 주 1회? — 짧을수록 복리가 빠르다)
- **증폭 계수**: 1명의 방문자가 다음 사이클에 몇 명을 데려오는가

## 1.3 Four Fits — "제품-시장 적합" 만으로는 못 큰다

Balfour. $100M까지 가려면 네 개의 적합이 **동시에** 맞아야 한다.

1. **Market–Product Fit** — 시장이 원하는 걸 만들었나
2. **Product–Channel Fit** — **제품이 채널에 맞게 생겨먹었나**
   ⚠️ *채널에 제품을 맞추는 것이지, 제품에 채널을 맞추는 게 아니다.*
   바이럴을 원하면 공유할 이유가 제품 안에 있어야 하고,
   SEO를 원하면 페이지가 검색어 단위로 쪼개져 있어야 한다.
3. **Channel–Model Fit** — 채널의 CAC를 수익 모델이 감당하나
4. **Model–Market Fit** — 시장 크기 × 객단가가 목표를 지탱하나

**진단 도구로서의 가치**: 성장이 안 될 때 "콘텐츠를 더 쓰자"가 아니라
*네 개 중 어디가 깨졌는지*를 먼저 찍는다.

## 1.4 AARRR + North Star + ICE/RICE — 측정과 우선순위

**AARRR (Dave McClure, 500 Startups)** — 해적 지표
Acquisition → Activation → Retention → Revenue → Referral

2026년 실무 조정점: **Retention이 1순위 레버가 됐다.**
전 채널 CAC가 매년 오르는 중이라, 획득보다 유지가 싸다.
Bain: 유지율 5% 개선 → 이익 25~95% 증가.

**North Star Metric** — 팀 전체가 보는 단 하나의 숫자.
AARRR 단계 중 하나를 NSM으로 뽑고, 나머지를 입력 지표(input metric)로 둔다.
좋은 NSM 조건: (a) 고객이 얻는 가치를 대변할 것 (b) 우리가 움직일 수 있을 것
(c) 매출과 선행 상관이 있을 것.

**ICE (Sean Ellis)** — Impact × Confidence × Ease, 각 1~10, 평균.
빠르고 주관적. 실험 백로그 정렬용.

**RICE (Intercom)** — (Reach × Impact × Confidence) ÷ Effort.
Reach가 들어가서 ICE보다 덜 낚인다. 로드맵용.

실무 조합: **NSM으로 방향 → AARRR로 병목 진단 → ICE/RICE로 실험 정렬 → Bullseye로 채널 결정.**

## 1.5 Digital PR / 데이터 저널리즘 — 2026년 최고 레버리지

2026년 현재 링크빌딩·권위 획득에서 가장 효율이 높은 방식.

핵심 논리: **기자는 인용할 숫자가 필요하다.**
어떤 주제에 대해 공개된 유일한 데이터를 우리가 갖고 있으면,
그 주제의 모든 기사가 우리를 출처로 링크한다.

작동하는 자산 유형 (링크 획득률 순):
1. 오리지널 데이터 스터디 / 설문
2. 독점 데이터셋 분석
3. 공개 데이터의 재가공 — *공개돼 있지만 아무도 집계 안 한 것*
4. 무료 툴 / 계산기
5. 전문가 코멘트 (뉴스재킹)

피칭 원칙: 보도자료가 아니라 **완성된 기사거리**를 준다.
데이터 + 시각화 + 서사 + 인용 가능한 한 문장.

2026년 변화: **브랜드 언급(unlinked mention)이 백링크보다 AI 검색 노출과 3배 강한 상관.**
링크를 못 받아도 이름이 언급되면 그게 자산이다.

## 1.6 Programmatic SEO — 2026년의 좁아진 문

Head Term × Modifier = Page Matrix.
예: `공유숙박` × `250개 시군구` = 250 페이지.

**2026년 3월 코어 업데이트가 판을 바꿨다.**
- `scaled content abuse`가 명시적 위반으로 지정
- 템플릿·AI로 찍어낸 유사 페이지 수천 개 → 순위 60~90% 증발
- 300자 미만 얇은 페이지 수백 개 → 도메인 전체 색인 삭제 위험

**살아남는 조건 (전부 충족해야 함)**
- 페이지마다 **고유한 실제 데이터**가 들어갈 것 (검증된 목록, 실시간 가격, 실측치)
- 문구만 바꾼 게 아니라 **숫자와 결론이 다를 것**
- 지역 고유 인사이트, 관련 리소스, 사용자 생성 콘텐츠 등 부가 가치
- 데이터가 없는 조합은 **페이지를 만들지 않을 것** ← 가장 자주 어기는 규칙

즉 2026년의 pSEO는 "페이지 양산"이 아니라 **"데이터가 있는 곳에만 페이지를 낸다"**.

## 1.7 AEO / GEO — AI 검색에 인용되는 법

- **AEO**(Answer Engine Optimization): AI가 *추출*할 수 있게 만들기
- **GEO**(Generative Engine Optimization): AI가 *신뢰하고 반복 인용*하게 만들기

측정된 효과 (인용률 상승):
- **인용문 추가 +27.8%**
- **통계 수치 추가 +25.9%**

구조:
```
SEO  → 검색됨(retrieval)
AEO  → 추출됨(extraction)
GEO  → 신뢰·재사용됨(trust & reuse)
```
GEO는 80%가 전략(포지셔닝·생태계 존재감·브랜드 권위), 20%만 기술.

실무 체크리스트:
- 명확한 질문형 H2 + 그 아래 2~3문장 직답
- 숫자에 출처·기준일 명시
- `Dataset` / `Article` / `FAQPage` JSON-LD
- 여러 사이트에 걸친 일관된 엔티티 표기

## 1.8 Engineering as Marketing — 툴이 콘텐츠보다 오래 산다

무료 툴/계산기/마이크로앱으로 고객을 획득.
B2B에서 가장 저평가된 채널.

왜 통하나: **복리로 쌓인다.** 광고는 예산 끄면 0이 되지만 툴은 몇 년을 끈다.
HubSpot의 Website Grader — 2008년 출시, 지금도 **월 65,000 방문**.

성립 조건: 툴이 (a) 진짜 문제를 풀고 (b) 우리 데이터가 있어야만 만들 수 있고
(c) 결과가 공유하고 싶게 생겨야 한다.

## 1.9 한국 시장의 구조적 특수성

**(1) 검색이 이원화돼 있다**
- 네이버 국내 점유율 50%+, 검색의 75% 이상이 모바일
- 네이버는 **자사 서비스(블로그·카페)를 외부 웹사이트보다 위에 노출**시킨다
- 외부 사이트를 네이버에 올리려면 **서치어드바이저(웹마스터도구) 등록 필수**
  → 등록 후 노출까지 14~16일
- 결론: **구글용 사이트 + 네이버용 블로그, 두 채널을 병행**해야 한다. 하나로는 반쪽이다.

**(2) 네이버 스마트블록 (2026 기준)**
- 하이퍼클로바X가 문맥을 읽어 "진짜 경험"인지 "광고글"인지 실시간 판별
- 상위 노출 글 평균 본문 **2,000~3,000자**
- 체류시간 **2분 30초~3분 이상** 필요
- **발행 후 24~48시간 반응**이 블록 진입을 좌우
- 퍼온 이미지보다 직접 제작 이미지가 훨씬 높은 점수
- 검색량 대비 문서수가 유리한 **복합 키워드**가 진입 속도를 결정

**(3) 커뮤니티가 검색을 대체한다**
한국은 특정 주제에 대해 검색보다 커뮤니티에서 답을 찾는 비중이 크다.
관련 커뮤니티 규모:
- **아이보스** — 마케터·사업자 34만 명
- **월급쟁이부자들(월부)** — 부업/N잡, 실제로 `N잡아카데미 숙박업` 시리즈 연재 중
- 네이버 카페·오픈채팅 — 에어비앤비 호스트 모임 다수

**(4) 보도자료 유통 구조**
- 뉴스와이어가 사실상 표준 배포망 (기자·언론사·포털·투자자)
- **설립 2년 이내 법인은 무료 배포** 지원 프로그램 있음
- 포털 전재 구조라 1건이 수십 개 매체로 복제된다

# PART 2. 이 제품의 진단

## 2.1 냉정한 산수 — 먼저 짚고 가야 할 것

| 항목 | 수치 |
|---|---|
| 외도민업 영업중 (우리 데이터) | **11,014곳** |
| 국내 에어비앤비 호스트 추정 | **약 14,000명** |
| 목표 | **일 1,000명** = 월 약 30,000 세션 |

**현역 호스트 전체가 매일 7%씩 방문해야 1,000명이 된다. 불가능하다.**

→ **1,000명/일은 "호스트 매체"로는 절대 도달 불가능한 숫자다.**
   도달하려면 독자 정의를 확장해야만 한다.

확장된 독자 정의 (이 순서로 크다):

| 세그먼트 | 규모감 | 검색 의도 | 사업 가치 |
|---|---|---|---|
| **예비 호스트 / N잡·부업 탐색층** | 수십만 | "에어비앤비 수익", "공유숙박 창업", "부업" | ★★★ 최고 (위홈 전환) |
| **부동산·소형 임대 투자자** | 수십만 | "○○구 숙박 수익률", "월세 vs 에어비앤비" | ★★☆ |
| 숙박업 종사자 (펜션·게하·모텔) | 수만 | "객실 점유율", "RevPAR" | ★★☆ |
| 현역 공유숙박 호스트 | 1.1~1.4만 | "외도민업 신고", "규제" | ★★★ (전환 최고, 물량 최저) |
| 정책·언론·리서치 | 수천 | "공유숙박 통계", "외도민업 현황" | ★☆☆ (물량 낮음, **PR 레버리지 최고**) |

⚠️ **솔직한 경고**: 트래픽을 늘리려면 예비 호스트·부업층으로 넓혀야 하는데,
이 층은 위홈 호스트 전환율이 현역 호스트보다 훨씬 낮다.
**"일 1,000명"과 "위홈 호스트 획득"은 부분적으로 상충하는 목표다.**
1,000명이 목표라면 이건 감수해야 한다. 이 문서는 1,000명 기준으로 짰다.

## 2.2 Four Fits 진단

| Fit | 상태 | 판정 |
|---|---|---|
| Market–Product | 데이터는 진짜고 독점적. 근데 대상 시장이 1.4만 명 | 🟡 제품은 좋은데 시장이 작다 |
| **Product–Channel** | **여기가 깨졌다.** 페이지 8개. 검색어 단위로 안 쪼개져 있음 | 🔴 **최우선 수리 대상** |
| Channel–Model | 콘텐츠·PR 중심이면 CAC 거의 0. 문제없음 | 🟢 |
| Model–Market | 수익 모델 = 위홈 호스트 유입. 리포트 자체는 무료 | 🟡 |

**결론: 병목은 콘텐츠 품질도, 데이터도 아니다. Product–Channel Fit이다.**
전국 250개 시군구 데이터를 갖고 있으면서, **검색 가능한 페이지는 8개뿐**이다.

```
      ┌──────────────────────────────────────────────┐
      │                                              │
  [행안부 원본 데이터 월간 갱신]                       │
      │                                              │
      ├──→ 250개 시군구 페이지 자동 갱신 ──→ 구글 검색 유입
      │                                              │
      ├──→ "이달의 발견" 1건 추출 ──→ 보도자료/커뮤니티 ──→ 기사·언급

      │                                              │      │
      └──→ 뉴스레터 발송 ──→ 재방문 ──→ 공유 ─────────────┘
                              │
                              ↓

                              │
```

**증폭 지점 3개**
1. 시군구 페이지는 한 번 만들면 매달 자동 갱신 → 색인 누적, 권위 누적

3. 구독자는 이탈하지 않는 한 매달 다시 온다 → 직접 트래픽의 바닥이 매달 올라감

**사이클 단축 실험**: 월간 → **주간 데이터 스냅샷**으로 가면 루프가 4배 빨리 돈다.

  "반반꿈"의 EP12가 이달의 발견과 정확히 같은 주제(서울/부산 vs 지방)를
  다뤄서 자연스럽게 데이터로 답을 보탤 수 있는 타이밍. 댓글 초안까지 준비됨.
- **카페는 위험 신호 확인됨** — 실사 중 "운영진이 경쟁 정보로 인식한 글은
  강제 퇴출한다"는 실사용자 후기 발견. 첫 몇 번은 링크 없이 활동만 하도록
  플레이북에 명시.
- 질문 유형별 재사용 답변 템플릿 4개(지역 추천·포화 여부·등록 수·규제) —
  전부 UTM 붙은 링크 포함, area 페이지·estimate.html·dashboard.html로 분기
- ⚠️ **홍보글 금지.** 커뮤니티 질문에 우리 데이터로 답하고, 근거로 링크를 단다.
